# 19. リスクと対策

影響: 事業・信頼・費用・納期 / 発生確度: 高・中・低

| # | リスク | 影響/確度 | 対策(設計への反映) |
|---|---|---|---|
| R-1 | UIと実態の乖離(停止中に「作業中」表示、根拠のない進捗) | 信頼/中 | イベントログからの状態導出のみ許可・heartbeat鮮度でstale表示・進捗率非表示(10, AC-9〜12)。**§13絶対条件のため最優先** |
| R-2 | 誤情報の公開(古いニュース・単一情報源・推測の断定) | 事業・信頼/中 | sources必須項目のスキーマ強制・QAの事実チェック・不確実は公開候補から除外・承認前に出典をUI表示(11, 13) |
| R-3 | 権利侵害(顧客名/画面の無許可公開・画像転載・推薦コメント脚色) | 事業・信頼/中 | customer_permissions構造管理・verbal_onlyは使用不可・blocked_rightsで機械的に停止(13)。Q4で運用確定 |
| R-4 | 承認バイパス(無承認公開) | 信頼/低 | 公開経路が「承認済みexport+人間の手動投稿」のみ。API導入後もcore層で承認チェック強制(12) |
| R-5 | 費用の暴走(API課金・有料サービス) | 費用/低 | MVPはAPIキー0個。API有効化はUIでの費用見積もり承認が必須+limits自動停止(14, Q2) |
| R-6 | Maxプラン利用枠の逼迫(他の開発作業と競合) | 納期・運用/中 | 日次生成上限(投稿3本)・共有コンテキストで消費削減・枠超過時はbudget_pausedで翌日継続(14)。運用が枠を圧迫する場合はAPI移行を判断材料に |
| R-7 | 代表者の30分/日が守れず承認が滞留 | 事業/中 | 承認キューsoft_cap(5件)で生成側を自動抑制・キーボード一括操作・「最低限モード」(6, 10) |
| R-8 | 1か月MVPの遅延 | 納期/中 | 縦切り実装・削減順の事前定義(テンプレ→カレンダー→会議自動化。DM支援は2026-07-13にスコープ外へ確定済み)・削減禁止項目の明示(17) |
| R-9 | Claude Code仕様変更(スキル・サブエージェント・モデル指定) | 納期/低 | 実装開始時に再確認する手順を明記・CLI境界に依存を集約(エージェントはCLIを叩くだけ)・指定不能時のフォールバック定義(9, 14) |
| R-10 | SQLite破損・誤操作によるデータ喪失 | 運用/低 | WALモード・日次14世代バックアップ・restore+doctor・append-onlyイベントから状態再構築可能(8) |
| R-11 | DM等の個人情報漏えい(ログ・Git・AI入力) | 信頼/低 | マスキング後にAIへ・ログはID参照のみ・data/はgitignore・secretスキャン(13, Q5) |
| R-12 | Instagramアカウントの制限(スパム的挙動と誤認) | 事業/低 | MVPは完全手動投稿のみ・自動化はMeta公式APIのみ・非公式自動化ツールを使わない(12) |
| R-13 | コンテンツの質が低く成果が出ない(承認率低迷) | 事業/中 | 週次会議での柱×形式の検証ループ・承認率/保存数をKPI化・30日で戦略再設定(15)。「継続>本数」の原則 |
| R-14 | ピクセルアート素材のライセンス問題 | 信頼/低 | CC0素材+ライセンス台帳(assets-license.md)・出所不明素材の使用禁止(10) |
| R-15 | AI出力のスキーマ逸脱・幻覚による破損データ | 運用/中 | CLIでのZod検証が唯一のDB書込経路・リトライ2回・失敗の可視化(7, 9) |

## エスカレーション基準(運用ルール)

- 公開後に事実誤り・権利問題が発覚 → 代表者が即時投稿削除/訂正 → 湊が原因分析 → QAチェックリスト更新(audit_log記録)
- 同種のタスク失敗が3日連続 → heavy昇格で原因分析 → 解消しなければ該当機能を一時停止し代表者へ報告
