# 00. エグゼクティブサマリー

## 何を作るか

**Bloom-L AI Company** — 代表者1人のフリーランス事業「Bloom-L」のInstagram運用を、AI社員9名(表示上)が調査・会議・企画・執筆・画像生成・品質確認・分析まで担い、代表者は1日30分の承認・判断・送信だけを行う仕組み。最初の実働部門は「Bloom-L AIマーケティング部」。

最終目的はフォロワー数ではなく、**泉州地域の見込み客からのDM相談 → 見積もり → 受注**である【確定】。

## システムの姿(MVP)

```
┌─ 代表者のMac(ローカル完結・追加費用0円) ─────────────────────┐
│                                                                │
│  ① Claude Code セッション(Maxプラン枠)                        │
│     /kickoff(始業コマンド)→ AI社長補佐が当日の優先度を決定    │
│     → 必要なAI社員(サブエージェント)だけを順次実行             │
│     → 成果物・イベントを CLI 経由で SQLite に記録              │
│                                                                │
│  ② Next.js ローカルWebアプリ(ダッシュボード)                  │
│     2Dピクセルアートのオフィス。AI社員が実タスク状態に          │
│     連動して席・会議室・品質管理室・社長室を移動                │
│     承認/却下/修正依頼、素材登録、日報・議事録・利用量の閲覧    │
│                                                                │
│  ③ SQLite + ローカルファイル(イベントログ=正)                 │
│     Google Drive と同一のフォルダ構造。後日アダプター交換       │
└────────────────────────────────────────────────────────────────┘
              ↓ 書き出し(画像PNG + キャプションtxt + チェックリスト)
       代表者が Instagram へ手動投稿(公開前承認は必須・自動投稿しない)
```

## 主要な設計判断(詳細は DECISIONS.md)

| # | 判断 | 結論(すべて【推奨】、承認対象) |
|---|---|---|
| D-03 | AI実行環境 | **Claude Codeセッション内で実行**(Maxプラン枠・公式CLI機能のみ)。Anthropic APIはアダプター定義のみ用意し、MVPでは呼ばない → 追加費用0円 |
| D-02 | データ保存 | SQLite(better-sqlite3 + Drizzle ORM)+ append-onlyイベントログ。将来Postgres/Tursoへ移行可能 |
| D-06 | ピクセルオフィス描画 | ゲームエンジン不使用。**DOM/CSS + スプライトシート**。アクセシビリティ・reduced-motion・1か月納期に最適 |
| D-09 | カルーセル画像生成 | **Satori(JSX→SVG)+ Sharp(→PNG 1080×1350)**。コードでテンプレートに文章・ロゴを流し込む。Canvaは補助 |
| D-04 | アプリとAIの連携 | アプリはAI認証情報を一切持たない。Claude Code → CLIスクリプト → SQLite → UIが読む、の一方向 + 承認だけUIがDBへ書く |
| D-12 | Instagram | MVPは**手動投稿**(書き出し+チェックリスト)。Meta API連携は移行条件を満たしてから第2段階 |

## 費用

- MVP追加費用: **0円/月**(Claude Maxプラン枠 + ローカル実行 + OSSのみ。上限5,000円/月を大きく下回る)【推奨】
- MaxプランがAPI課金を含むとは仮定しない【確定】。API利用は明示的なオプトイン+費用見積もり提示後のみ

## 1か月MVPに含むもの / 含まないもの(§18準拠)

**含む**: ピクセルオフィス(実タスク連動)/ 始業コマンド / 投稿テーマ・文章・カルーセル案生成 / 品質確認 / 承認・却下・修正依頼 / 投稿用書き出し / 実績素材→投稿化 / 日報・利用量表示

**含まない(第2段階以降)**: **DM支援(2026-07-13のスコープ変更でMVPから除外)** / Instagram自動投稿・Meta API / クラウド常時稼働 / LINE通知 / メール通知 / 複数SNS同時運用 / Google Drive API連携(ローカルフォルダで同構造を先行)

## 代表者への質問5問(✅ 2026-07-13 回答済み — 記録は `DECISIONS.md`)

1. **Meta連携**: 現状不明。MVPは手動投稿まで。第2段階で設定確認の上、条件を満たせばGraph API予約投稿を検討
2. **予算**: MVP追加費用は原則0円。有料機能は費用と必要性の事前提示+代表者承認まで有効化しない
3. **通知**: MVPはダッシュボードのみ。メールは第2段階、Gmail API+OAuth第一候補(SMTP原則不使用)
4. **実績公開**: 使用前にメール/DMで公開範囲を確認し同意記録を保存。記録まで「権利確認待ち」
5. **DM本文**: 要約のみ保存(マスキング→AI処理後に原文破棄)。※DM支援機能自体は第2段階

## リスク上位3件(詳細は 19)

1. **UIと実態の乖離**(動いていないのに「作業中」表示)→ イベントログ由来の状態導出 + ハートビート鮮度チェックで構造的に防止
2. **誤情報・著作権・無許可の顧客情報公開** → 情報源記録の必須化、公開前承認の強制、許可データの構造管理
3. **代表者の30分/日が守れない** → 承認キューの一括操作、1日の生成量上限、優先度の自動絞り込み
