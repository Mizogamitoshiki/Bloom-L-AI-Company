# 10. ピクセルオフィスUI/UX・画面仕様

## 1. 描画方式の決定【D-06。比較はDECISIONS.md】

**DOM/CSS + スプライトシート**(ゲームエンジン不使用)。
オフィスはCSS Gridのタイルマップ、社員はabsolute配置の`<button>`要素+スプライトPNG(`image-rendering: pixelated`)、移動はCSS transform遷移、歩行はCSS `steps()` アニメーション。

- 理由: 社員9体+部屋数個なら性能余裕 / DOM要素なのでキーボード操作・フォーカス・スクリーンリーダー対応が自然に可能 / reduced-motion対応がCSSだけで完結 / 1か月MVPで最も確実
- ピクセル素材: 自作またはCC0素材。`docs/assets-license.md`(実装時作成)に生成元・ライセンス・利用条件を記録【確定§13】

## 2. 状態→演出のマッピング(演出は導出データ)【確定§13】

| 実状態(リデューサ出力) | 部屋/位置 | アイコン+テキストバッジ(色に依存しない) |
|---|---|---|
| researching(調査中) | 自席(PC操作モーション) | 🔍相当のSVG+「調査中」 |
| meeting(会議中) | 会議室 | 「会議中」 |
| creating(制作中) | 自席 | 「制作中」 |
| qa(品質確認中) | 品質管理室 | 「品質確認中」 |
| awaiting_approval(承認待ち) | 社長室前・承認ボックス付近 | 「承認待ち(N件)」 |
| done_today(完了) | 自席(伸びモーション) | 「本日完了」 |
| idle(待機) | 休憩スペース | 「待機」 |
| error(エラー) | 自席(エラーマーク) | 「エラー: 理由要約」 |
| budget_paused(予算停止) | 休憩スペース | 「予算停止」 |
| stale(状態不明) | その場で停止 | 「状態不明(最終更新 N分前)」 |

**信頼性の実装規則**(§13絶対条件 → 受け入れ基準AC-9〜12):
- 演出状態はUI側で `deriveDisplayState(events)` により毎回導出。DBに「演出状態」を保存しない
- heartbeatが10分途絶えたrunningタスクは必ず `stale` 表示に落とす
- 進捗率バーは実装しない。表示は実イベントのある「段階名」のみ
- エラー・待機理由・承認待ち理由はバッジ+詳細パネルで常時確認可能

## 4. 主要画面仕様

### S-01 オフィス(ホーム)
- 構成: 上部ステータスバー(本日のrun状態 / 承認待ちN件 / エラーN件 / 利用量メーター)+ オフィスマップ + 右側ミニログ(最新イベント10件)
- 部屋: 執務室(9席)/ 会議室 / 品質管理室 / 社長室+承認ボックス / 休憩スペース / 準備中4部屋(営業・Web制作・開発・経理管理。小さく、グレー表示+「準備中」札)
- 代表者アバターは社長室に常駐。承認待ちがあると社長室の上に件数バッジ
- 操作: 社員クリック/Enter → S-02。承認ボックスクリック → S-03。準備中部屋クリック → 役割と解放条件のモーダル(稼働情報は一切出さない)
- **アニメーションOFFトグル**(ヘッダー常設)+ `prefers-reduced-motion` 自動respect → OFF時は同情報を**テーブル形式の一覧**(社員/状態/現タスク/最終更新)で表示【確定§13】
- 空状態: 初回起動時「まだ稼働していません。Claude Codeで /kickoff を実行してください」+手順リンク

### S-02 社員詳細パネル(右ドロワー)【§13必須項目を全掲載】
- ヘッダー: 名前・役職・現在状態バッジ
- 本文: 現在のタスク(なければ「なし」)/ 開始時刻 / 使用モデルプロファイル / 入力資料(リンク) / 現在の段階(イベント由来) / 成果物一覧(版付き) / 実行ログ(task_eventsのタイムライン) / 推定使用量 / エラー詳細 / 次の予定(計画されたタスク)
- 操作: タスクの停止・キャンセル(確認ダイアログ+audit_log記録)

### S-03 承認キュー
- リスト(左): 承認待ち投稿・返信案。優先度順。`blocked_rights` は「権利確認待ち」タブに分離
- プレビュー(右): カルーセル画像スワイプ / キャプション全文 / ハッシュタグ / QAレポート(チェック項目と判定) / 引用sources(URL・確認日) / 使用素材の許可状態
- 操作: **承認 / 却下 / 修正依頼**(修正はテンプレート: 文言・デザイン・事実・その他+自由記述)。キーボードショートカット(A/R/E)【推奨】
- 承認後: 「書き出し」ボタン → export_bundle生成 → 「投稿済みにする」で published 記録(published_atは代表者操作時刻)

### S-06 素材・実績登録
- 実績: 顧客名・URL・画面キャプチャ・ハイライト+**公開許可の記録**(範囲チェックボックス+証跡ファイル添付)。許可未記録は一覧で警告表示
- 素材: `data/workspace/04_content-input/new/` へのドロップ+メタ入力 → 企画タスク自動生成

### S-07 DM支援【第2段階】
- 取り込みフォーム(貼り付け→マスキングプレビュー→保存)/ 分析結果カード(要約・分類・見込み度・緊急度・不足質問)/ 返信案2案(コピー用ボタン、編集可)/ 「送信済みにする」記録
- 常時注意書き: 「送信はInstagramアプリから代表者が行います。AIは送信しません」

### S-08 レポート / S-09 議事録
- 日報: 本日の完了/失敗/承認状況/明日の予定/利用量。週報・月報: KPI推移+分析コメント+改善提案
- 利用量: タスク別・モデル別の推定量。API有効時のみ金額表示

## 5. UI/UX共通規約【確定§13】

- 業務データ(タスク名・本文・数値)は通常フォント(Noto Sans JP等)。ピクセルフォントは装飾見出しのみ
- アイコンは単一SVGセット(例: Lucide、ISCライセンス)。絵文字を操作アイコンにしない
- 全操作がキーボード到達可能。フォーカスリング常時可視。コントラスト比WCAG AA(4.5:1)以上
- 状態は「色+アイコン+テキスト」の3重表現。タップ/クリック領域は44×44px以上
- ブランドカラーは `config/brand-tokens.json` → CSS変数。未設定時はプレースホルダーパレットで動作
- レスポンシブ: デスクトップ最適化。スマホは S-01を一覧モード固定+S-03/S-08 を閲覧・承認可能(S-07は第2段階実装時に追加)【確定: 最低限閲覧可】
