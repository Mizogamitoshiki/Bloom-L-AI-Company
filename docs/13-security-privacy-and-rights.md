# 13. セキュリティ・プライバシー・権利

## 1. 秘密情報管理【確定§17】

| ルール | 実装 |
|---|---|
| APIキー・認証情報をコード/Gitへ保存しない | `.env` は `.gitignore`。`.env.example` のみコミット(キー名と説明だけ、実値なし) |
| MVPで扱う秘密情報を最小化 | MVPは外部APIキー0個(Claude Code認証はClaude Code自身が管理し、本システムは触れない) |
| 将来のキー(Meta/Drive/Gmail) | `.env` + macOSのファイル権限600。UIに表示しない。ログ出力禁止 |
| Git衛生 | pre-commitでsecretスキャン(gitleaks等の無料ツール)【推奨】。`data/` `runs/` `.env` はgitignore |

## 2. 個人情報・ログ【確定§17】

- **task_events / audit_log / 日報にはID参照のみ**を記録し、DM本文・顧客連絡先を含めない(CLIの記録関数でスキーマ的に強制)
- DM取り込み時のマスキング(通常コード): 電話番号・メールアドレス・住所らしき文字列を `[電話番号]` 等に置換してからAIへ渡す【確定: AIへ渡す前のマスキング】(DM支援機能は第2段階)
- DM原文の保持【Q5確定 2026-07-13】: マスキング→AI処理後に原文破棄。DBには要約・分類・対応状況のみ保存
- runs/ 配下の当日コンテキストは7日で自動削除【推奨】

## 3. 顧客の公開許可管理【確定§7・§17】

- `customer_permissions` に 顧客×範囲(名前/URL/画面/推薦コメント)×状態 を構造管理(→08)
- 【Q4確定 2026-07-13】投稿使用前にメールまたはDMで公開範囲を確認し、同意記録を保存する。状態が `recorded`(証跡あり)の範囲のみ投稿に使用可能。`verbal_only` は使用不可(QAが `blocked_rights` で止める)。記録取得まで無断使用しない
- 推薦コメントは本人の内容確認+掲載許可の記録があるまで「顧客の声」として掲載しない。許可前の脚色・断定禁止【確定】
- 許可の証跡(DMスクショ等)は `07_customer-permissions/` に保存し、公開素材フォルダ(03_portfolio等)と分離【確定: 公開可能素材と機密素材の分離】
- 公開可能な実績画像は `04_portfolio-assets/<portfolioItemId>/` に分離保存する。UIアップロードはPNG/JPEG/WebP・20MB以下のみ。パストラバーサル、絶対パス、ルート外symlink、SVG、壊れた/巨大画像を拒否する
- `scope.screenshot=true` のときだけ画像をレンダラーへ渡す。specへ元素材SHA-256を刻印し、QA・承認・export時に再計算して差し替えを検知する

## 4. 著作権・情報品質【確定§15】

- 他者画像の無断転載禁止(パイプライン上、外部画像はそもそも取り込み経路がない)
- 引用は必要最小限+出典明記。ニュース投稿は自分の言葉での要約+出典表示をテンプレートに組み込み(tpl-newsに出典スロット必須)
- sourcesの必須項目(URL・発行元・公開日・確認日)が欠けた情報は投稿へ引用不可(スキーマで強制)
- 効果保証・誇大表現の禁止語リストを `config/` に置き、QAチェックリストに組み込む

## 5. 監査・運用統制【確定§17】

- 承認・却下・修正依頼・公開記録・許可記録・設定変更・タスク停止/再開はすべて `audit_log`(append-only)
- タスクの停止・再開・キャンセル操作をUIとCLIの双方に用意
- 再試行上限2回(タスク)/ 再計画上限2営業日 → 超過は人間判断へ
- バックアップ: 日次DB+素材差分(14世代)、週次zip→Drive手動(→08)。復旧手順は `company restore` + doctor

## 6. アプリ自体の境界

- Next.jsは `localhost` バインドのみ(外部公開しない)。認証はMVPでは設けない(単一ユーザー・ローカル限定)【推奨。クラウド化時に認証必須(→18)】
- CSPと外部リクエスト最小化: ダッシュボードは外部CDNに依存しない(フォント・アイコン同梱)

## 7. クラウド化に備えた設計の残し方【確定§17】

| 項目 | MVPでの準備 |
|---|---|
| 認証 | ユーザー概念(actor列)を最初からデータに持つ(MVPは`owner`固定) |
| 権限 | 操作はすべてユースケース関数経由(後からガードを挿せる) |
| 暗号化 | 保存時暗号化が必要な列(permissions証跡パス等)を特定済みにしておく |
| テナント分離 | MVPは単一テナントだが、エンティティにtenant前提のID設計(ULID)を採用 |

### V3追補(2026-07-13 実装反映・レビュー指摘1対応)
- 公開許可は**scope 4項目(name/url/screenshot/testimonial)の個別許可**。`scope_json`はZod検証で解析し、不正・欠落は全不許可として扱う
- approvedでも `scope.name=false` なら実名は使用不可。匿名利用は `anonymousAllowed=true` **かつ証跡(evidencePath)がある場合のみ**。approvedの記録には証跡+scope個別指定が必須(一括固定scopeは廃止)
- 許可範囲外の顧客名・URL・お客様の声は通常コード(`findCustomerDataViolations`)がQA時・承認時に検出して拒否する
- **AIプロンプトへ渡す前のマスク**: CLIの`portfolio-list`は許可範囲でマスク済みビュー(`listPortfolioForAi`)のみを返す(scope.screenshot=falseの素材パス、scope.url=falseのURL、scope.testimonial=falseの声は渡らない)
- 許可変更後は承認時の再検査で旧画像(旧表示名)との不整合を検出し、再レンダリング+再QAを要求する
- URL(source/顧客サイト)は**http/httpsのみ許可**し、正規化して保存する(javascript:/data:/file:等を拒否)
