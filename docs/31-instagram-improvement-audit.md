# 31. Instagram 反響改善 調査レポート(2026-08-22)

依頼: 代表者「投稿内容や画像が微妙で反響が悪い。実装はしなくていいので改善方法を調査してほしい」
方法: DB(`data/company.db`)・書き出し済み全PNG(実物を目視)・テンプレート実装・戦略文書・2026年時点のInstagram一次動向の照合。
**このレポートはコードを変更していない。** 測定用の一時スクリプトは実行後に削除した。

---

## 0. 結論

反響が悪い直接原因は「デザインのセンス」ではなく、**構造的な3つ**である。

1. **測っていない** — 公開9本すべて実績値が未入力。改善ループが一度も回っていない。
2. **画像が「配布資料」であって「スクロールを止めるもの」ではない** — 実測で紙面の **95%が無地**。
3. **見つけてもらう導線がない** — リール0本、シェア(送る)依頼0件、実績投稿0本、遷移先リンク未整備。

3つとも、センスではなく**設定と仕組みで直せる**。

## 2. 画像の欠陥(証拠つき・重大度順)

### D-1【P0】情報密度が低すぎる。原因はコードで特定できる

`tpl-news.ts:26` の `evenSpread()` は `flexGrow:1` のスペーサーを要素の前後に挟み、**要素間の余白を均等に引き伸ばす**。要素が2つしかないページでは1350pxを2要素で分け合うため、上・中・下に巨大な空白ができる。

これは紫苑QA(v10/v11)への対応として入った修正だが、**空白の「配置」を直しただけで「量」を直していない**。`docs/22` の **CR-02(P0)「紙面の大半が空白」は未解決のまま**であり、v3で決めた「単一小カード+大余白を禁止」「情報モジュール2つ以上を必須」というルールも、`design-qa.ts` には検査が実装されていない(見ているのは寸法・ロゴ・fingerprint・重複だけ)。だから**スカスカのままQAをpassする**。

### D-2【P0】ロゴが白い箱で貼られている

```
data/workspace/01_brand/logo.png    162x62   hasAlpha: no
data/workspace/01_brand/logo@2x.png 486x186  hasAlpha: no
```

**アルファチャンネルがない。** 薄青地(`surfaceDark #eef1f7`)や濃紺のページでは、ロゴの周りに白い長方形がはっきり出る(08-10投稿の 03.png / 05.png / 06.png で確認できる)。**透過PNGに差し替えるだけで、コード変更ゼロで全ページが直る。** 費用対効果が最も高い1手。

### D-3【P1】表紙の下半分が「目次」

全テンプレートの表紙に `contentsCard`(「この投稿の構成」「この投稿でわかること」)が入る。フィードで指を止める唯一の1枚に、読む前の目次が置かれている。

さらに、この投稿で一番強い素材である **34.5% / 28.0% という数字が表紙に出ていない**。design-systemには `stat`(132px)と `statBlock()` が定義済みなのに、**news/compare/howtoのどのテンプレートも一度も呼んでいない**(grep結果:参照は`components.ts`の定義のみ)。用意した最強の武器が未使用。

### D-4【P1】図に中身がない

`tpl-news.ts` の `changeFlow` に流し込まれるのは `opinion.heading` と `impact.heading`。08-10投稿の3枚目で実際に描画された文字は「**私たちの見立て**」「**推測ですが**」。矢印つきの箱が3つ並ぶが、伝わる情報はゼロ。被覆率2.5%のページはこれ。

### D-5【P1】1投稿の中にデザイン言語が2つ

07-27公開分は **1枚目がCanva(濃紺・明朝・金枠)、2枚目以降がSatori(白地・ゴシック)**。別アカウントの投稿を並べたように見える。しかもCanva側の1枚目は主役が**空の金枠**で、ロゴではなく**文字「Bloom-L」**が入っている(brand-manifestの「ロゴを文字で代用しない」に抵触)。

### D-6【P1】写真も人も実物も一枚もない

19本すべて図形とテキストのみ。唯一の実物素材(JFリフォーム様のPC/スマホモック、被覆率16.1%)は**投稿になっていない**。HP制作会社が、作ったHPを一度も見せていない。

### D-7【P2】CTAが型として弱い

`ctaPage()` のバッジは柱から自動決定され、実質「保存」「プロフィールへ」の2択。**1枚目のフッターにも「プロフィールへ」がある** — 読み始める前に外へ出そうとしている。

## 3. 内容の問題

- **C-1 主語がBloom-L側のまま。** V9で「場面起点」に切り替えたはずだが、08-10投稿の結論は「私たちは差が開くと考えています」で、読者の行動が決まらない。
- **C-2 泉州である必然性が薄い。** 「業種を問わず」「泉州で自分ごとに置き換えるなら」= 誰にでも当てはまる = 誰にも刺さらない。地名はハッシュタグと1文だけ。
- **C-3 保存する理由が弱い。** チェックリスト・比較表は保存価値があるが、ニュース型は数字1個で保存動機が立たない。
- **C-4 シェア(友達に送る)を一度も依頼していない。** 2026年のInstagramで**非フォロワーに届く最大の信号は sends/reach**(いいねの3〜5倍の重み)。9本すべてでゼロ。
- **C-5 キャプションの事故。** 07-27公開分は **CTAとハッシュタグが二重に入ったまま公開されている**(`caption.txt` 実物)。`guards.ts` に重複検査がない。
- **C-6 遷移先がない。** CTAスライドは「プロフィールへ / リンクから詳しく見られます」と言うが、`docs/01` `docs/03` `docs/15` はいずれも「**自社HP完成後は**」と書いている = **Bloom-L自身のHPがまだない**。HP制作会社が「リンクから詳しく」と言って、その先がない状態は、獲得の穴であると同時に信用の問題でもある。

---

## 4. 運用の問題

- **頻度が不安定。** 4日で5本 → 7日空き → 9日空き → 12日空き。Instagramは継続性を評価するので、週3本を出して2週止まるより**週2本を切らさない**ほうが効く。
- **9本ではどんな分析も成立しない。** `docs/27 §13` が自認しているとおり「傾向の可能性」止まり。判断に足る本数(10本以上)にまず届かせる必要がある。
- **ストーリーズが止まっている。** 4枚作って以降ゼロ。既存フォロワーとの接触頻度が事実上ない。

## 5. 改善方法(優先順位つき)

### P0 — 今週やる。コード変更はほぼ不要

**① 実績値を入れる(最優先)**
9本分をInstagramインサイトから `/publish` に転記し、滞留16タスクを消化する。**ここが埋まらない限り、以降の改善は全部「勘」**になる。見るべきは:リーチ / **非フォロワー比率** / 保存 / **シェア(送信)** / プロフィールアクセス / **1枚目→最終枚の到達率**。
→ 「反響が悪い」が、届いていない(リーチ)問題なのか、届いたが止まらない(1枚目)問題なのか、読まれたが動かない(CTA)問題なのかが、ここで初めて切り分けられる。

**② ロゴを透過PNGに差し替える**
`data/workspace/01_brand/logo.png` / `logo@2x.png` をアルファ付きで置換するだけ。全ページの白箱が消える。作業10分。

**③ 実績投稿を1本出す**
JFリフォーム様(許可記録あり・素材あり・被覆率16.1%)。**今ある中で唯一、見栄えがして、かつBloom-Lにしか作れない**コンテンツ。柱⑤が0%である是正にもなる。

### P1 — 2〜4週

**④ 情報密度を機械検査に入れる**
本文ページの被覆率下限(例:8%)を `design-qa.ts` の検査項目に追加し、`evenSpread()` による引き伸ばしをやめる。**空白を均等に配るのではなく、1ページに情報モジュールを2つ以上載せる**(docs/22 v3で決めたルールを、宣言ではなく検査で強制する)。

**⑤ 表紙を「目次」から「数字・断言・実物」へ**
`contentsCard` を表紙から外し、未使用の `statBlock()`(132px)を使う。1枚目フッターのCTAバッジは削除。

**⑥ 枚数を7〜10枚へ**
2026年のカルーセルは7〜10枚のほうがエンゲージメントが高い。ただし**空のページを足すのではなく、1ページ1メッセージに割り直す**(密度改善と同時にやらないと悪化する)。

**⑦ シェアCTAを型に加える**
「同じことで困っている人に送ってあげてください」を CTA 選択肢に追加し、保存CTAと使い分ける。sends/reach は非フォロワー到達の最大レバー。

**⑧ Canvaマスターを表紙以外にも作る**
`docs/29 §1.5` で `copy-design → read-design → edit-design(replace_text) → export` のE2Eが実証済み(文字は一字一句そのまま入る)。**今あるマスターは表紙1枚だけ**なので、D-5の混在事故が起きている。本文・比較・CTAのマスターを代表者が手作りすれば、**意匠は人間・流し込みは決定的**という最も事故の少ない構成になる。

### P2 — 1〜3か月

**⑨ リールを始める。** 非フォロワー到達の主戦場で、現在0本。`schemas.ts` に `video_script` はあるがレンダリングがない。凝る必要はなく、**制作画面の録画+字幕**で十分(実物が映ること自体が差別化)。配分の目安はリール6:カルーセル4。

**⑩ 題材を「実物・現場・失敗」へ寄せる。** 制作の裏側 / Before-After / 断ったほうがいいケース。一般的なHP啓蒙は競合と差がつかない。

**⑪ 自社HPを出す。** CTAの着地点がない状態を解消する。HP制作会社の自社HPは、それ自体が最大の実績。

**⑫ 週2本を切らさない。**

## 6. 検証の回し方(1変数ずつ・4週)

V6の improvement_proposal の仕組みは動くのに一度も使われていない。実績値が入り次第、次の順で回す。

| 週 | 変える変数 | 見る指標 |
|---|---|---|
| 1 | 表紙(目次あり / 数字主役) | 1枚目→2枚目の到達率 |
| 2 | CTA(保存 / シェア) | sends ÷ reach |
| 3 | 題材(一般HP論 / 実績) | 非フォロワーリーチ、プロフィールアクセス |
| 4 | 密度(現行 / 被覆率8%以上) | 最終枚到達率、保存率 |

計測10本未満のあいだは断定禁止(`docs/27 §2`)。「傾向」として扱う。

---

## 7. 触らなくてよいもの

反響の原因ではないので、改善のために緩めない:公開ガード(QA・権利・承認)、価格、日次上限、断定表現・効果保証の禁止、owner専用の判断境界。**土台は正しい。** 問題は土台の上に載っている密度・題材・導線・計測にある。

---

## 8. このレポートで確認できていないこと

- **Instagramアカウント本体を見ていない**(プロフィール文・ハイライト・リンク・フォロワー数・実際のインサイト)。リポジトリにアカウント情報の記録がなく、外部への接続も行っていない。プロフィール側の受け皿(§3 C-6)は代表者の確認が必要。
- 被覆率は本レポート独自の近似指標であり、業界標準の値ではない。**同じ物差しでの相対比較**として使う。
