# 17. 1か月MVPロードマップ

## 1. スコープ判定(§18準拠+2026-07-13承認)

### MVPに含む(受け入れ基準の対象)
1. 2Dピクセルオフィス(実タスク状態連動・9状態表示・詳細パネル・準備中部屋)
2. `/kickoff` 始業コマンド(日次ワークフロー一巡・異常終了回収・日報)
3. 投稿生成パイプライン(テーマ→コピー→カルーセルPNG。テンプレート5種のうち最低3種: howto/news/portfolio)
4. QA→承認・却下・修正依頼(理由記録・監査ログ)
5. export_bundle書き出し+手動投稿チェックリスト+published記録
6. 実績素材登録→投稿化(公開許可管理を含む)
7. 日報+推定利用量表示
8. デモモード・バックアップ/復旧・基本テスト

### MVPに含まない(第2段階以降)
**DM支援(取り込み・マスキング・分析・返信案 — 2026-07-13の代表者指示でMVPから除外。設計は 05/06/08/10/13 に維持し、第2段階で実装)** / Meta API連携(自動・予約投稿)/ メール・LINE通知(実装時はGmail API+OAuth第一候補、SMTP原則不使用)/ Google Drive API / インサイト自動取得 / 複数SNS / 動画自動生成(台本まで) / クラウド稼働 / tpl-checklist・tpl-faq(余裕があれば)

## 2. 週次計画(4週+バッファ)

前提: 実装はClaude Code(Opus)、代表者は毎日30〜60分の確認。各週末に動くものを確認する縦切り方式(プロンプト2と整合)。

### Week 1: 骨格 — 「イベントが流れ、オフィスに映る」
- リポジトリ初期化(Next.js+TypeScript strict+Drizzle+Vitest)、core層(スキーマ・リデューサ・状態機械)
- company CLI(run-start/plan/submit/イベント記録/seed)
- オフィス画面S-01(静的マップ+デモデータで社員状態表示+一覧モード)
- **完了確認**: seedデータでオフィスが実状態を表示。リデューサのunitテスト通過

### Week 2: パイプライン — 「投稿案が生まれる」
- エージェント定義9種+kickoffスキル(まず 葵→昊→琴葉 の最小経路)
- レンダラー(Satori+Sharp、tpl-howto)+文字あふれ検査
- 詳細パネルS-02、承認キューS-03(承認/却下/修正+audit_log)
- **完了確認**: 実際の/kickoffで投稿案1本がPNG付きで承認キューに届き、承認→書き出しできる

### Week 3: 品質と実績 — 「安心して公開できる」
- QAエージェント+チェックリスト+blocked_rights、リサーチ(sources必須項目強制)
- 実績登録S-06+customer_permissions+実績→複数投稿展開
- tpl-news / tpl-portfolio、パイプラインS-04・カレンダーS-05
- 日報・利用量、limits(上限・budget_paused)
- **完了確認**: 実績投稿がQA→権利チェック込みで一巡。上限超過でbudget_paused表示

### Week 4: 仕上げ — 「毎日回せる」
- レポートS-08・議事録S-09・設定S-10
- 週次会議フロー、バックアップ/restore/doctor、E2E・a11y、README・運用手順書
- 余裕があれば: tpl-checklist / tpl-faq(DM支援は余裕があっても前倒ししない — スコープ確定済み)
- **受け入れテスト**: `20-acceptance-criteria.md` のMVP対象項目を代表者が検収 → **運用開始**

### バッファ・調整ルール(2026-07-13 承認)
